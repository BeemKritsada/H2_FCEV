# ส่งมอบงาน Phase 4 — Batch 8: ปัญหาใหญ่ 3 ประการของรถยนต์ไฮโดรเจน

ตรวจวันที่ 14 ตุลาคม 2026 ที่ `C:\web\H2_FCEV` ทำเฉพาะฉาก “ปัญหาใหญ่ 3 ประการ” และโค้ดกลางที่ฉากนี้ต้องใช้ ไม่ deploy และไม่เพิ่มสไลด์ใหม่

## ลำดับฉาก (ต้องตัดสินใจต่อ)

บรีฟเรียกฉากนี้ว่า “Scene 24” ของงานนำเสนอ 24 ฉาก แต่ `scene-config.ts` ปัจจุบันมี **30 ฉาก** หลังเพิ่ม Batch 7 (21 รถไฟขนส่งสินค้า, 22 รถจักรเหมือง, 23 แผนที่การใช้งานรถไฟ) ฉากเนื้อหาเรื่องนี้คือ `scene-challenges` ซึ่งอยู่**ลำดับ 29** ถัดจากฉาก 24–28 เดิม (ห้องเย็น, อุตสาหกรรม, รถไฟเฉพาะทาง, ภูมิภาค, ข้อได้เปรียบ) และตามด้วยฉากปิด

งานนี้แทนเนื้อหาของ `scene-challenges` เดิมโดย**ไม่เปลี่ยนลำดับ** ถ้าต้องการให้ฉาก 23 → ฉากนี้ต่อกันโดยตรง ต้องตัดสินใจเรื่องฉาก 24–28 เดิม (ย้ายหรือเอาออก) ซึ่งอยู่นอกขอบเขตบรีฟ ฉากผูกกับ id จึงใช้งานได้ทุกตำแหน่ง ส่วนชุดตรวจ browser หาลำดับจาก config เอง

ระหว่างที่ทำงาน มีอีก session เพิ่ม Batch 7 ลงไฟล์กลางพร้อมกัน (`scene-config.ts`, `SceneContainer.tsx`, `i18n/index.ts`, `batch5/assets.ts`) จึงแก้ไฟล์เหล่านี้เพียงบรรทัดเดียวแบบเพิ่มต่อท้าย

## 2. Layout

- **บน:** eyebrow + หัวเรื่องใหญ่ + คำบรรยายหนึ่งบรรทัด (ซ่อนคำบรรยายบนเดสก์ท็อปที่สูงไม่เกิน 820px เพื่อให้ทั้งสไลด์อยู่ในจอเดียว)
- **กลางซ้าย:** ภาพหลักขนาดใหญ่ ภาพทั้งสามซ้อนกันและโหลดไว้ล่วงหน้า มีป้ายลำดับ 01–03 และเครดิตบนภาพ
- **กลางขวา:** “ปัญหาที่ n จาก 3”, ชื่อปัญหา, ตัวเลขใหญ่, คำอธิบายสั้นใต้เส้นแบ่ง
- **ใต้ภาพ:** ปุ่มเลือกปัญหา 3 ปุ่ม มีภาพย่อ ไอคอน ลำดับ และชื่อสั้น ปุ่มที่เลือกมีขอบ/พื้นฟ้าและแถบบน ส่วนปุ่มอื่นใช้ภาพย่อสีจางแต่ยังคลิกได้
- **ล่าง:** สไลด์ต้นฉบับ 12, หมายเหตุขอบเขตของปัญหาที่เลือก, เครดิต/ใบอนุญาตภาพ
- ปัญหา 02 มีจุดชี้ “หัวจ่ายไฮโดรเจน” บนภาพ ระบุ 35 MPa “พบได้มากกว่า” (ฟ้า) และ 70 MPa “ยังมีจำนวนจำกัด” (กรอบส้ม) ใช้สีตัวเลขเดียวกันเพื่อไม่ให้ดูเป็นการจัดอันดับ และมีหมายเหตุว่าเป็นมาตรฐานการเติม ไม่ใช่สมรรถนะ
- ปัญหา 03 ใช้สีส้มอย่างจำกัด: หน่วย หยวน/กก., เส้นเน้นใต้ตัวเลข และเส้นซ้ายของข้อความเปรียบเทียบ ไม่มีตัวเลขต้นทุนต่อ 100 กม.

## 3. การเลือกปัญหา

- เริ่มที่ปัญหา 01 ทุกครั้งที่เข้าฉาก
- เมื่อเลือกปัญหาอื่น ภาพเดิมจะจางออกและหดเล็กน้อยใน 0.55 วินาที ภาพใหม่จางเข้าและลดจาก scale 1.035 เป็น 1 ใน 0.8 วินาที จากนั้นข้อมูลชุดใหม่ไล่ขึ้นทีละรายการใน 0.55 วินาที ไม่มีการหมุนหรือเคลื่อนกล้อง
- ความทึบของภาพควบคุมด้วย GSAP ทั้งหมด ทุกครั้งที่คลิกจะ `killTweensOf` ก่อน และเริ่มจากค่าความทึบปัจจุบัน แผงข้อมูลผูก key กับปัญหาที่เลือก จึงไม่ค้างข้อมูลเก่า ทดสอบคลิกสลับเร็ว 20 ครั้งแล้ว: เหลือภาพที่มองเห็นเพียงภาพเดียว ไม่มีภาพค้างครึ่งจาง และปุ่ม/ชื่อเรื่องตรงกับการคลิกสุดท้าย
- Ambient: ภาพถ่ายขยายช้า 4% ใน 18 วินาที, รถลอยขึ้น 4px, แสงกวาดจาง ๆ ทุก 11 วินาที และวงชี้หัวจ่ายเต้นเบา ๆ ปุ่มที่ไม่ได้เลือกไม่เคลื่อนไหว เมื่อหยุดการนำเสนอทุกอย่างหยุด และ reduced motion ปิดทั้งหมด

## 4. การนับตัวเลข

ใช้ `SceneNumberSequence` เดิม (ตัวละ 0.85 วินาที เว้น 0.12 วินาที `power2.out` ทีละตัว) ผ่าน `StateNumberSequence` ที่ซ้อนเป็นรายปัญหา จำสถานะไว้ใน session set เดียวกับ App (`scene-challenges#purchase` / `#refueling` / `#operating`)

| ปัญหา | ลำดับการนับ | เมื่อไหร่ |
|---|---|---|
| 01 | 300,000+ → 1.5–4× | เข้าฉากครั้งแรก |
| 02 | 35 → 70 (MPa) โดยแถว 70 สว่างขึ้นเมื่อเริ่มนับ | เลือกครั้งแรก |
| 03 | 44.5 แล้วตามด้วยเส้นส้ม | เลือกครั้งแรก |

ผู้นำเสนอใช้ปุ่มได้ทันที ไม่ต้องรอให้นับครบ ถ้ากลับไปปัญหาที่เคยดูหรือกลับเข้าฉาก ตัวเลขแสดงค่าสุดท้ายทันที การเปลี่ยนภาษาไม่ทำให้นับใหม่ (ทดสอบสลับภาษาขณะกำลังนับแล้ว) ปุ่ม “เริ่มนำเสนอใหม่” ล้างความจำนี้ ถ้าหยุดการนำเสนอหรือเปิด reduced motion จะแสดงค่าสุดท้าย และ screen reader อ่านค่าจริงคงที่ เลขลำดับฉากและป้าย 01–03 ไม่ถูกนับ

`1.5–4×` ใช้ `decimals: [1, 0]` ให้ทศนิยมแยกแต่ละปลาย ไม่ใช่ “1.5–4.0×”

## 6. ภาพที่ยังขาด / ควรทำต่อ

- **ภาพสถานีในจีน:** ภาพ 02 และ 03 เป็นภาพตัวอย่างนอกจีน ฉากจึงติดป้ายไว้ ถ้ามีภาพสถานีจีน (เช่น Sinopec) ที่ใบอนุญาตชัดเจน ควรใช้แทน
- **ความสมจริงของภาพ 01:** เป็นภาพเรนเดอร์ ส่วน 02–03 เป็นภาพถ่าย ทั้งหมดดูสมจริงและโทนใกล้กัน ไม่มีภาพการ์ตูน แต่ถ้าต้องการให้เป็นภาพถ่ายทั้งชุด ต้องใช้ภาพถ่ายรถเซลล์เชื้อเพลิงจริงในสตูดิโอ
- ใบอนุญาต CC BY-SA 4.0 ของภาพ 03 กำหนดให้งานดัดแปลง (ภาพที่ครอปแล้ว) ใช้ใบอนุญาตเดียวกันและต้องให้เครดิต ซึ่งแสดงไว้ที่ footer แล้ว

## 7. ผลทดสอบ TH/EN

- ข้อความสนับสนุนทั้ง 6 ข้อความ (3 ปัญหา × 2 ภาษา) ตรงตามบรีฟทุกตัวอักษร และหัวเรื่อง TH/EN ตรงตามที่กำหนด
- คีย์ TH/EN ตรงกันทุกตัว ตัวเลขตรงกับ section `adoption-barriers` (สไลด์ 12) ทั้งสองภาษา
- สลับภาษาแล้วยังอยู่ปัญหาเดิม (ทดสอบ EN→TH→EN) ไม่ย้ายฉาก และไม่นับใหม่
- หน่วย: EN “RMB”, “RMB/kg”; TH “หยวน”, “หยวน/กก.”; MPa เหมือนกันทั้งสองภาษา
- หัวเรื่องและคำบรรยายเรียงแนวตั้งในทั้งสองภาษา เพื่อไม่ให้ layout ขยับเมื่อสลับภาษา
